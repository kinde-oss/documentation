Kinde publishes a remote [MCP](https://modelcontextprotocol.io) server that lets Grok work with your Kinde environment in natural language. Once connected, you can ask Grok to look up users, inspect organizations, review roles and permissions, and make routine changes.

You can connect from grok.com, the Grok Bot, or the Grok CLI. grok.com and the CLI use an **Environment API key**. The Grok Bot asks you to sign in with your Kinde account the first time you use the connector. Signing in from grok.com isn't available yet; see the note at the end of this page.

## What you need

- A Kinde business with the **Environment API keys** feature enabled.
- An Environment API key enabled for the MCP server. Create one in **Settings > APIs > Kinde Management API > API keys**, choose its scopes, and copy the value; Kinde shows it only once. See [Create an Environment API key](/mcp-servers/manage-kinde-account-with-ai-agents/#step-1-create-an-environment-api-key).
- The [Grok CLI](https://docs.x.ai/build/features/mcp-servers), or a Grok plan that includes connectors on grok.com. On Grok Business and Enterprise, a team admin provisions connectors first.
- Your environment's MCP URL: `https://YOUR_BUSINESS.kinde.com/mcp`. If you use a custom domain, use that domain instead.

## Option 1: Grok.com (Web)

1. Go to `grok.com/connectors`, or open **Connectors** from the menu.
2. Select **New Connector**, then **Custom**.
3. Enter a name, such as `Kinde`, and the **Remote MCP server URL**: `https://YOUR_BUSINESS.kinde.com/mcp`.
4. If the form has an **Authorization** or bearer token field, enter `Bearer YOUR_API_KEY`, including `Bearer ` and the space.
5. Select **Add Connector**.

If the form only asks for OAuth details (client ID, authorization endpoint, token endpoint), Grok can't connect to Kinde from grok.com yet. Use the Grok Bot or the Grok CLI instead.

## Option 3: Grok CLI

Add the server with the key as a header. Keep the key in an environment variable so it stays out of your shell history:

```bash
export KINDE_API_KEY="YOUR_API_KEY"
grok mcp add --transport http kinde https://YOUR_BUSINESS.kinde.com/mcp \
  --header "Authorization: Bearer ${KINDE_API_KEY}"
```

Check the connection:

```bash
grok mcp doctor kinde
```

The equivalent entry in `config.toml` is:

```toml
[mcp_servers.kinde]
url = "https://YOUR_BUSINESS.kinde.com/mcp"
headers = { "Authorization" = "Bearer YOUR_API_KEY" }
```

Run `grok mcp list` to see the server, and `grok mcp remove kinde` to remove it.

## Use the connector

Ask in plain language, for example:

- "How many users are in the _Acme_ organization?"
- "List every user who has the _admin_ role and which organizations they hold it in."
- "Create a new role called _Support Agent_."

Grok only sees the tools your key's scopes cover. Read-only tools run without asking; tools that create, change or delete data are annotated so Grok asks you to confirm before running them.

### Signing in with your Kinde account

[AI agent sign-in](/mcp-servers/sign-in-with-your-kinde-account/) lets Claude and ChatGPT connect without a key by signing in with a Kinde account. The Grok Bot prompts you to sign in the first time you use the connector. grok.com doesn't register itself with Kinde the way those assistants do, so sign-in from grok.com isn't supported yet. Use an Environment API key there, or use the Grok CLI.

### Troubleshooting FAQs

<details>
<summary>No tools appear after connecting</summary>

The key is missing scopes, isn't enabled for the MCP server, or the Environment API keys feature isn't enabled. Add the scopes and reconnect.

</details>

<details>
<summary>"Authentication required" or the connection is rejected</summary>

Check that the key is active, that it is the environment key created for the MCP server (it starts with `k_live_`), that the header value starts with `Bearer ` followed by a space, and that the MCP URL belongs to the environment the key was created in.

</details>

<details>
<summary>grok.com asks for OAuth client details</summary>

Kinde sign-in isn't available from grok.com yet. Use the Grok CLI with an Environment API key.

</details>

### Security best practices

- Scope the key tightly. Prefer read-only scopes unless Grok genuinely needs to make changes.
- Use a dedicated key for Grok so you can revoke it without affecting other integrations, and rotate or revoke it from **Settings > APIs > Kinde Management API > API keys** if it is exposed.
- Keep the key out of prompts and chat history. Put it in the connector configuration or an environment variable only.
- Review every write action before approving it.

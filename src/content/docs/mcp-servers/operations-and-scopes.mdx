The Kinde Management MCP server exposes the [Kinde Management API](/kinde-apis/management/) as tools, one per operation, covering create, read, update and delete wherever the API supports them. What an assistant can actually use depends on how it connected:

- With an **Environment API key**, the assistant sees the tools covered by the scopes on the key.
- With **[sign-in](/mcp-servers/sign-in-with-your-kinde-account/)**, the assistant sees the tools covered by the access level set for the person's team role.

Each tool is annotated so assistants treat it correctly: read-only tools run without asking, and tools that create, change or delete data ask for confirmation first.

## What the server covers

| Area                        | What you can manage                                                                                                                                                    |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Users                       | List, get, create, update and delete users; identities, properties, feature flag overrides, password, sessions and MFA                                                  |
| Organizations               | List, get, create and update organizations; membership, user roles and permissions, properties, feature flag overrides, connections, MFA, passkeys, logo and handle    |
| Roles and permissions       | Full create, read, update and delete for roles and permissions; role permissions and system permissions                                                                |
| Applications and APIs       | Application create, read, update and delete, plus connections, access roles, properties and token settings; APIs, API scopes, and API-to-application scope grants      |
| Authentication              | Connections (SSO and social), callback and logout URLs, passkey and MFA policy                                                                                         |
| Feature flags and properties | Feature flag create, read, update and delete; custom properties and categories                                                                                        |
| Access and provisioning     | API keys (create, rotate, revoke, verify), organization invites, SCIM directories                                                                                       |
| Environment and business    | Environment settings and variables, subscribers, webhooks, events, business profile, and reference data such as industries and time zones                              |

A few operations are intentionally not exposed: deleting an organization, billing operations, and rotating a SCIM directory's secret.

## Access levels for sign-in

When someone connects by signing in with their Kinde account, their team role's access level decides which tools appear:

| Access level                        | Tools                                                                            |
| ----------------------------------- | -------------------------------------------------------------------------------- |
| **No access**                       | None. The person can't connect.                                                  |
| **Read only**                       | Every read tool.                                                                 |
| **Read and write (no delete)**      | Every read, create and update tool, except the credential-minting tools below.   |
| **Full access (including delete)** | Every tool.                                                                      |

Credential-minting tools are available at **Full access** only: creating API keys, creating applications, authorizing applications on an API, and rotating application secrets. They are held back from _Read and write_ because a credential created through them would outlive the person's access to the connector.

## Secrets are redacted

Whichever way an assistant connects, credentials never reach it. These fields are replaced with `[redacted]` in every tool result: an application's `client_secret`, a connected app's `access_token`, a SCIM directory's `secret_token`, and the `key` value of a newly created or rotated API key. The rest of the response is unchanged. Read those values in the Kinde dashboard instead.

### How do I grant scopes to my MCP server?

Scopes are granted when you [create an Environment API key](/mcp-servers/manage-kinde-account-with-ai-agents/#step-1-create-an-environment-api-key). Select the scopes you need, and only those. You can create a second, more privileged key later once you're comfortable with what the assistant does.

For sign-in, there are no scopes to pick. An owner or admin sets an [access level for each team role](/mcp-servers/sign-in-with-your-kinde-account/#step-2-set-access-levels-for-each-team-role).

### How do I check which tools my assistant has?

Ask it. For example, "What Kinde tools do you have?" lists the tools the current key or access level covers. If a tool you expect is missing, add the scope to the key and reconnect, or ask an owner or admin to raise your role's access level.

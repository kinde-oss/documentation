You can allow users to use their phone as a primary method for authentication. This is a passwordless method, where the user is sent a verification code via SMS (or [WhatsApp](/authenticate/authentication-methods/whatsapp-authentication/) when configured). SMS can also be included as a secondary factor if you have [multi-factor authentication](/authenticate/multi-factor-auth/about-multi-factor-authentication/) set up.

## Kinde default SMS

By default, Kinde sends authentication SMS from its own shared service. You can use this in live environments on every plan. You do not need a third-party SMS provider to go live.

- On the Free plan, Kinde default SMS is limited to 10 SMS per month.
- On paid plans (Pro, Plus, Scale), Kinde default SMS is not capped. Usage is billed per message — see [Kinde pricing](https://kinde.com/pricing/).
- SMS sent as a second factor for MFA through Kinde’s default service counts toward the same Free plan limit and paid-plan usage as sign-in SMS.

We recommend connecting your own SMS provider for best deliverability, and so you can control the sender ID or source number. Your own provider is uncapped and is not billed by Kinde. This is a recommendation, not a requirement.

Kinde supports:

- [Twilio](https://www.twilio.com/en-us)
- [Sinch Engage](https://developers.sinch.com/docs/engage-api/) (formerly MessageMedia)

Connecting your own SMS provider gives you:

- Full control over SMS delivery nuances, such as Sender ID, country registrations, and detailed delivery metrics.
- The ability to register dedicated short codes or sender IDs in countries that have strict SMS sending regulations (such as Ireland, New Zealand, and Canada), which greatly improves deliverability.
- Access to delivery logs and other service quality details for troubleshooting.

## Set up Twilio

You need a [Twilio](https://www.twilio.com/en-us) business account to send from your own numbers.

Phone authentication interactions are also known as [A2P (Application to Person)](https://www.twilio.com/docs/glossary/what-a2p-sms-application-person-messaging) messaging. Before you implement A2P, check if you need to register your business for 10DLC (10 Digit Long Code) support to be able to send messages, as this is required in some locations.

We also recommend you check [Twilio’s guidelines for setting up messaging](https://www.twilio.com/en-us/guidelines/sms), and carefully follow procedures for registration and SMS policies for all relevant countries.

You’ll need the following details from the dashboard of your [Twilio account](https://www.twilio.com/en-us):

- **Account SID** — The Account SID provided by Twilio
- **Auth token** — The auth token provided by Twilio
- **Messaging Service SID** or **From** number — Your Twilio messaging service SID or a Twilio-issued phone number

![Twilio account info](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/1da93a0a-9fd3-437f-5357-be90f3f3c200/public)

Refer to the [Twilio documentation](https://www.twilio.com/docs/messaging) for assistance setting up.

### Configure Twilio

1. In Kinde, go to **Settings > Environment > Messaging > SMS**.
2. In the **SMS provider** section, select **Twilio** in the **Provider** field.
3. In the **Twilio settings** section, enter your **Account SID** and **Auth token**.

   ![twilio details](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/4c857ff9-ff87-44ea-a488-3e2b511caf00/public)

4. Under **SMS source**, select either **Use message service** (default) or **Use "From number"**. Verification codes will be sent from whichever you choose.

   <Aside>

   The Twilio messaging service is more suitable for global applications as it detects where the sign-in comes from and sends from an appropriate number.

   </Aside>

5. Depending on your selection in the previous step:

   - If you selected **Use message service**, enter your **Messaging Service SID**.
   - If you selected **Use "From number"**, enter your Twilio-issued phone number in the **From** field. Include the country code (`+##`) with no spaces (maximum 14 characters).

   ![Twilio config](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/749a80bc-d6b7-40b0-950a-650c7775b900/public)

6. Switch on **Allow Kinde to use fallback SMS provider** if you want Kinde to switch to a fallback provider if your primary provider is experiencing issues. Delivery cannot be guaranteed.

   ![option to use kinde sms as fallback](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/9bdd2ef1-c308-4307-c84e-bc8ffdbfe200/public)

7. Select **Save**.

<Aside>

For security reasons, Kinde never displays a stored auth token, so the **Auth token** field is blank when you return to the page. If **Twilio** is already your active provider, leave **Auth token** blank to keep the existing auth token. If you are switching to **Twilio** from another provider, you must enter the auth token.

</Aside>

## Set up Sinch Engage

You can connect your own [Sinch Engage](https://app.sinch.com) (formerly MessageMedia) account to send authentication SMS messages. SMS messages sent through your own Sinch Engage account are not billed by Kinde.

You’ll need the following details from your Sinch Engage account at `app.sinch.com` (see the [Sinch Engage API documentation](https://developers.sinch.com/docs/engage-api/) for details):

- **API key** — Created under **Settings > API Settings** in your Sinch Engage account at `app.sinch.com`
- **API secret** — The API secret created alongside your Sinch Engage API key. Sinch displays this secret only once when the key is created, so store it securely
- **Account region** — The region where your Sinch Engage account is hosted:
  - **Asia Pacific (au.app.api.sinch.com)** (default)
  - **Europe (eu.app.api.sinch.com)**
- **Source number** (optional) — A dedicated phone number, alphanumeric sender ID, or short code registered with Sinch
- **Source number type** (optional) — How Sinch Engage should interpret your source number (`Detect automatically`, `International`, `Alphanumeric`, or `Short code`)

<Aside>

**Account region** selects the regional Sinch Engage REST API endpoint (`au.app.api.sinch.com` or `eu.app.api.sinch.com`) that Kinde calls to send messages. It must match the region where your Sinch Engage account is hosted, and is not a restriction on the countries you can send messages to. The legacy MessageMedia endpoint (`api.messagemedia.com`) is not used.

</Aside>

### Configure Sinch Engage

1. In Kinde, go to **Settings > Environment > Messaging > SMS**.
2. In the **SMS provider** section, select **Sinch Engage** in the **Provider** field.
3. In the **Sinch Engage settings** section, enter your **API key**.
4. Enter your **API secret**.
5. Select your **Account region**:
   - **Asia Pacific (au.app.api.sinch.com)** (default)
   - **Europe (eu.app.api.sinch.com)**
6. (Optional) Enter a **Source number**. Leave this field blank to use your Sinch Engage account default.
   - Dedicated source numbers are not enabled by default on Sinch Engage accounts and must be registered with Sinch first.
   - For international numbers, include the country code with no spaces (for example, `+61400000000`).
7. (Optional) If you entered a **Source number**, select a **Source number type**:

   - **Detect automatically** (default) — Sinch Engage detects the sender type automatically.
   - **International** — Standard international E.164 phone number.
   - **Alphanumeric** — Registered alphanumeric sender ID.
   - **Short code** — Registered short code.

   <Aside>

   **Source number type** is only used when a **Source number** is set (selecting a specific source number type while leaving **Source number** blank will fail validation). Because Sinch Engage’s automatic detection can be inaccurate for alphanumeric sender IDs and short codes, select **Alphanumeric** or **Short code** explicitly when using those sender types.

   </Aside>

8. Switch on **Allow Kinde to use fallback SMS provider** if you want Kinde to switch to a fallback provider if your primary provider is experiencing issues. Delivery cannot be guaranteed.
9. Select **Save**.

<Aside>

For security reasons, Kinde never displays a stored API secret, so the **API secret** field is blank when you return to the page. If **Sinch Engage** is already your active provider, leave **API secret** blank to keep the existing API secret. If you are switching to **Sinch Engage** from another provider, you must enter the API secret.

</Aside>

## Configure phone SMS auth in Kinde

After you set this up, you can use SMS for both phone authentication and SMS MFA.

1. In Kinde, go to **Settings > Environment > Messaging > SMS**.
2. In the **Details** section, select the **Default country** that you want to show on the authentication screen when users sign in.
3. In the **SMS provider** section, select a **Provider**:

   - **Kinde default** — Uses Kinde’s own SMS service. No credentials are needed. This works in live environments.
   - **Twilio** — Uses your own Twilio account. See [Set up Twilio](#set-up-twilio).
   - **Sinch Engage** — Uses your own Sinch Engage account. See [Set up Sinch Engage](#set-up-sinch-engage).

   The configuration fields below the selector update automatically to match the provider you choose.

4. If you selected **Twilio** or **Sinch Engage**, enter your provider credentials and choose whether to switch on **Allow Kinde to use fallback SMS provider**.
5. Select **Save**.

## Switch on SMS for MFA

By default, your configured SMS service is also enabled for SMS MFA. If you previously turned off the **Use this service for SMS MFA** option and want to re-enable it:

1. In Kinde, go to **Settings > Environment > Messaging > SMS**.
2. Scroll to the bottom and switch on **Use this service for SMS MFA**.
3. Select **Save**.

## Switch on phone authentication for an application

1. Go to **Settings > Environment > Authentication**.
2. In the **Passwordless** section, select **Configure** on the **Phone** tile.
3. Switch on the auth method for the applications you want.
4. Select **Save**.

## Switch on SMS as a factor in MFA

If MFA is required or optional for your users, you may want to use Kinde default SMS or your own SMS provider for SMS MFA.

1. Go to **Settings > Environment > Multi-factor auth**.
2. Under **Additional authentication methods**, switch on **SMS**.
3. Select **Save**.

## SMS message format

You can’t customize the code message that user’s receive. We use a standard format as follows, to allow for easier translation.

      ```
      Your verification code is [xxxxxx]
      ```

## Connection ID

When you configure phone authentication, you’ll see that a Connection ID is automatically assigned. If you’re building a [custom authentication experience](/authenticate/custom-configurations/custom-authentication-pages/), you’ll need the ID to trigger the phone authentication workflow.

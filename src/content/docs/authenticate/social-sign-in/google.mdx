Let users sign up and sign in with their Google account. You can try this with Kinde's Google app, then create your own Google app before you go to production.

<Aside title="Google does not allow sign in auth to work in webview">

Google does not support auth in a webview. If a user opens your sign-in window inside another app, such as Instagram or Facebook, Google returns an error.

</Aside>

## Test Google sign-in (non-production)

Use this to try the sign-in flow. Kinde connects to Google with its own OAuth client. Replace that client with your own before production, as described in [Create your own Google app](#create-your-own-google-app).

1. Sign in to Kinde.
2. Go to **Settings > Environment > Authentication**.
3. In **Social connections**, select **Add connection**.
4. In the **Add social connection** dialog, select **Google**, then select **Next**.

   <Aside>

   Selecting **Next** creates the connection immediately. The connection remains if you later select **Cancel**.

   </Aside>

5. Scroll down and switch on Google for each application that should use it.
6. Select **Save**. The **Continue with Google** button shows on the Kinde hosted sign-in pages. Your application does not need a new deploy.
7. Open the application and select **Sign up** or **Sign in**.
8. Select **Continue with Google** and finish signing in.
9. In Kinde, go to **Users**. The new user is listed there.

## Create your own Google app

<Aside type="warning" title="Social sign in for production environments">

Before you make your production environment live, add your own Google app's Client ID and Client secret in the Kinde connection. Blank fields use Kinde's app credentials, which poses a security and performance risk, and makes it difficult to change auth providers without service disruptions for your users.

</Aside>

### What you need

1. A [Kinde](https://app.kinde.com/register) account. You can [sign up for free](https://app.kinde.com/register).
2. A [Google Cloud](https://cloud.google.com/) account with [2-Step Verification](https://myaccount.google.com/signinoptions/twosv) turned on.

### Copy the callback URL

1. In Kinde, go to **Settings > Environment > Authentication**.
2. If Google is already listed under **Social connections**, select **Configure** on the Google tile. Otherwise select **Add connection**, select **Google**, then select **Next**.

   ![kinde authentication page showing the google social connection](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/254caf8d-8320-467b-8fa5-1e98b064b000/socialsharingimage)

3. In **Callback URL**, copy the **Kinde domain** value. It is a full HTTPS URL, for example `https://yourdomain.kinde.com/login/callback`.

   ![kinde authentication page showing the google social connection with the callback url](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/ac2ec324-3c03-4b69-d9f1-d40087432100/socialsharingimage)

   To show your own domain on the Google sign-in screen, turn on **Use custom domain instead** and copy that callback instead. See [Show your own domain on the Google sign-in screen](#show-your-own-domain-on-the-google-sign-in-screen).

   <Aside>

   If you use custom domains for more than one organization, copy every organization callback. Add each one in the Google client, and include `https://` on every URL.

   </Aside>

4. Select **Save**.

### Create a Google Cloud project

Create a project for this sign-in so its settings stay separate from your other Google Cloud apps.

1. Sign in to the [Google Cloud console](https://console.cloud.google.com/). Your Google account needs 2-step verification turned on.
2. Select the project picker in the top bar, then select **New project**.
3. Enter a **Project name**, for example, your app or business name. Google generates a **Project ID** from the name. Select **Edit** to change the ID. The ID is fixed once the project is created.
4. For **Parent resource**, keep **No organization** or select your organization, then select **Create**. It takes a few seconds to create the project.

   ![google cloud new project form](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/818d16f8-2da9-4b2e-44fd-b873c4785300/socialsharingimage)

5. In the notification that appears, select **Select Project**. Check that the project picker in the top bar shows your new project before you continue.

### Set up Google Auth Platform

1. In the console, go to **Google Auth Platform**. Because this is a new project, you'll see **Google Auth Platform not configured yet**. Select **Get started**.

   ![google auth platform overview showing get started](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/d3fd9685-9a1e-471b-33f6-b27df2203300/socialsharingimage)

2. In **App Information**, enter an **App name** (shown to users when they sign in) and select a **User support email**. Select **Next**.
3. In **Audience**, select **External**, then select **Next**. Select **Internal** only if all your users are in your own Google Workspace organization.

   ![google auth platform project configuration on the audience step](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/aae5f461-7c66-4d13-4473-acac35fb5f00/socialsharingimage)

4. In **Contact Information**, enter the email addresses Google should use to contact you about the project. Select **Next**.
5. In **Finish**, select the **I agree to the Google API Services: User Data Policy** checkbox, then select **Continue**.
6. Select **Create**. A message confirms **OAuth configuration created!**

### Add test users

New apps start in **Testing**. Only the test users you add can sign in. There is a cap of **100** users, counted over the lifetime of the app. The app can stay unverified while it is in **Testing**.

1. In **Google Auth Platform**, select **Audience**.
2. Under **Test users**, select **Add users**.
3. Enter the email addresses of the people who will test sign-in, then select **Save**.

   ![google auth platform audience page in testing](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/c57af0be-4fe7-4085-d96a-759458e8c900/socialsharingimage)

Leave the app in **Testing** until you [publish it](#publish-the-app).

### Create the OAuth client

1. In **Google Auth Platform**, select **Clients**, then select **Create client**.
2. For **Application type**, select **Web application**.
3. Enter a **Name** for the client, for example, `Kinde`. Users don't see this name.
4. Leave **Authorized JavaScript origins** empty for Kinde-hosted sign-in.
5. Under **Authorized redirect URIs**, select **Add URI** and enter each Kinde callback you copied, including `https://`. For example, `https://<your_kinde_subdomain>.kinde.com/login/callback`. If you use custom domains, also add each organization callback, for example `https://auth.yourdomain.com/login/callback`.

   ![create oauth client form with web application and redirect uri](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/a79b9cf5-2cbf-431a-beb2-4758dc3cd900/socialsharingimage)

6. Select **Create**.
7. In the **OAuth client created** dialog, copy the **Client ID** and **Client secret**, or select **Download JSON**. Store them somewhere safe. Google shows the client secret only in this dialog. The **Client ID** stays visible under **Clients**.

   ![oauth client created dialog with the client id and client secret](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/a024ec24-1c77-4c0b-a094-ea4a4a302200/socialsharingimage)

8. Select **OK**.

<Aside>

It may take 5 minutes to a few hours for Google settings to take effect. If sign-in fails with a redirect error straight after you create the client, wait a few minutes and try again.

</Aside>

### Add the credentials to Kinde

1. In Kinde, go to **Settings > Environment > Authentication**.
2. In **Social connections**, select **Configure** on the Google tile.
3. Under **Details**:
   1. **Connection ID** is read-only.
   2. **Connection name**: an internal name to identify this connection.
   3. **External name**: the label on the hosted sign-in button. The default is **Google**.
4. Under **Provisioning**, keep **Email address trust** set to **Trust**. Google verifies email addresses. For how the options work, see [Trusting emails from providers](/authenticate/about-auth/identity-and-verification/#trusting-emails-from-providers).

   ![configure google connection dialog with trust selected for email address trust](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/bf1c6a8e-cddb-4f2f-21ce-c8ecc1edc300/socialsharingimage)

5. Under **Keys**, paste the **Client ID** and **Client secret** from Google. In production, these are your own app's credentials.
6. Under **Callback URL**, confirm the HTTPS callback matches the **Authorized redirect URI** you added in Google. To use a custom domain, turn on **Use custom domain instead** and see [Show your own domain on the Google sign-in screen](#show-your-own-domain-on-the-google-sign-in-screen).

   ![configure google connection dialog with client id, client secret, and callback url](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/cbd638a8-feb0-4b1e-cfa4-39ce8ebeaa00/socialsharingimage)

7. Under **Permissions**, leave **Email address** checked. Kinde requires basic profile permissions automatically.
8. Under **Applications**, turn on Google for each application that should use it. Enable only one Google connection per application. If two are enabled for the same app, the sign-in page shows two identical **Continue with Google** buttons. If you need both, set a distinct **External name** on each. You can also manage connections under **Applications > [app] > Authentication**.
9. Two settings can stay at their defaults:
   1. **Allow passkeys for users of this connection** is off. Turn it on to offer passkey setup after sign-in, and when passkeys are mandatory. See [Enable Passkeys to sign in users](/authenticate/authentication-methods/passkeys/).
   2. Under **Advanced**, add [upstream params](/authenticate/auth-guides/pass-params-idp/) to pass to Google. For example, `prompt=select_account` forces the Google account selector.
10. Select **Save**.

### Publish the app

Move the app to **In production** when anyone with a Google account should be able to sign in. Until then, only the test users you added can sign in.

1. Finish **Branding**: app name, user support email, and developer contact. **Publish app** stays unavailable until Branding is complete.
2. On **Audience**, select **Publish app**.

## Scopes (optional)

Adding scopes in **Data Access** is optional for basic Kinde sign-in. By default no scopes are listed. Sign-in still works, because Kinde requests `openid`, `profile`, and `email`.

If you add scopes, go to **Data Access**, select **Add or remove scopes**, and use **Manually add scopes** with the full `https://` strings:

- `https://www.googleapis.com/auth/userinfo.email`
- `https://www.googleapis.com/auth/userinfo.profile`
- `openid`

![google auth platform data access page with the update selected scopes panel open](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/4a6e5a50-f5b9-43ef-b850-88ad3f514400/socialsharingimage)

## Show your own domain on the Google sign-in screen

Without a verified brand, Google's account chooser shows **"to continue to"** the domain of your Authorized redirect URI. The app name and logo appear only after brand verification. See [Manage OAuth App Branding](https://support.google.com/cloud/answer/15549049?hl=en).

The default Kinde callback is on a `*.kinde.com` host, so the chooser shows **kinde.com**. That is expected.

A custom-domain callback changes the domain Google shows.

1. Use a custom domain that is already **Provisioned** in Kinde. See [Use a custom domain with Kinde](/build/domains/pointing-your-domain/), including [Add the custom domain to social sign-in](/build/domains/pointing-your-domain/#add-the-custom-domain-to-social-sign-in).
2. In the Google connection, under **Callback URL**, turn on **Use custom domain instead**, select the callback (for example `https://auth.yourdomain.com/login/callback`), and select **Save**.

   ![configure google connection dialog with use custom domain instead turned on](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/57380a51-6048-47b0-61f1-946b867bcb00/socialsharingimage)

3. In the Google Cloud client, add that same URL as an **Authorized redirect URI**. You can keep the `kinde.com` callback as well.
4. In **Branding > Authorized domains**, add the custom domain's root, for example `yourdomain.com`, not the `auth.` hostname. This is likely needed.

   {/* TODO(Tamal): Confirm whether Branding > Authorized domains must be updated manually with the custom domain's root, or whether Google adds it automatically when you add the redirect URI. The client form says URI domains are added automatically. The successful 16 Nov 2026 test also added the root domain manually. Treat it as likely needed until confirmed. */}

5. Wait for settings to take effect, which can take 5 minutes to a few hours. Google may return **Error 400: redirect_uri_mismatch** shortly after you save. This is often the delay, so wait and retry before you change anything else.
6. Start sign-in on the custom domain. Your app's Kinde domain, often `KINDE_ISSUER_URL`, must be the custom domain. See [Use a custom domain with Kinde](/build/domains/pointing-your-domain/). If users still arrive through the `kinde.com` host, the chooser still shows **kinde.com**.

The chooser then shows **"to continue to"** your domain, for example **yourdomain.com** when the callback is `https://auth.yourdomain.com/login/callback`. The developer-info popup shows the app name as that domain.

![google account chooser showing to continue to a custom domain](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/193e70ed-d66e-49d1-521b-4c1e985fd000/socialsharingimage)

![google developer info popup showing the custom domain as the app name](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/8ab39a85-e180-4996-b30a-562926405800/socialsharingimage)

Brand verification is a later step, if you want the app name and logo on the Google screen. It needs a home page on a domain verified in Google Search Console, a privacy policy, and a logo. See [Manage OAuth App Branding](https://support.google.com/cloud/answer/15549049?hl=en). Basic Google sign-in works without brand verification.

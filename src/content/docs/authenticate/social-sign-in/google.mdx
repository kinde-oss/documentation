Let users sign up and sign in with their Google account. You can try this with Kinde's Google credentials, then create your own Google app before you go to production.

<Aside title="Google does not support sign-in in a webview">

If a user opens your sign-in window inside another app, such as Instagram or Facebook, Google returns an error.

</Aside>

## Test Google sign-in (non-production)

Use these steps to try the sign-in flow. Kinde connects to Google with its own OAuth client. Replace that client with your own before production, as described in [Create your own Google app](#create-your-own-google-app).

1. Sign in to Kinde.
2. Go to **Settings > Environment > Authentication**.
3. In **Social connections**, select **Add connection**.

   ![add connections setting window](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/7f572e6f-47be-4cca-0440-86f3354d9000/socialsharingimage)

4. In the **Add social connection** dialog, select **Google**, then select **Next**.

   ![add social connection dialog](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/2e7def75-568d-4d25-1bf2-e5f7dc09bb00/socialsharingimage)

   <Aside>

   Selecting **Next** creates the connection immediately. The connection remains if you later select **Cancel**.

   </Aside>

5. Scroll down and turn on Google for each application that should use it.
6. Select **Save**. The **Continue with Google** button appears on the Kinde-hosted sign-in pages. You do not need to redeploy your application.
7. Open a [Kinde-enabled application](/get-started/guides/byo-code) and select **Sign in** or **Sign up**.

   ![application sign in page](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/cc6f0fde-659b-4730-523c-372ce0e08f00/socialsharingimage)

8. Select **Continue with Google** and finish signing in.

   ![google sign-in flow](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/8eed3b2d-f0db-478a-6132-5e86c873be00/socialsharingimage)

9. In Kinde, go to **Users**. The new user is listed there with Google as the identity provider.

   ![users page with new user listed with Google as the identity provider](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/4ef951c9-57d0-482c-dd41-7fa64d82fe00/socialsharingimage)

   <Aside>

   Kinde creates two identities: one for the user's email address and one for the user's Google account. **Email address trust** for the Google connection is set to **Trust** by default, so Kinde merges the two identities. See [Trusting emails from providers](/authenticate/about-auth/identity-and-verification/#trusting-emails-from-providers).

   </Aside>

<Aside type="warning" title="Social sign-in for production environments">

Before you make your production environment live, add your own Google app's **Client ID** and **Client secret** to the Kinde connection. If those fields are blank, Kinde uses its own app credentials. That is a security and performance risk, and it makes changing identity providers disruptive for users. The next section shows how to add your credentials.

</Aside>

## Create your own Google app

### 1. Copy the Kinde callback URL

1. In Kinde, go to **Settings > Environment > Authentication**.
2. If Google is already listed under **Social connections**, select **Configure** on the Google tile. Otherwise, select **Add connection**, select **Google**, then select **Next**.

   ![kinde authentication page showing the google social connection](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/f96a3eed-584b-4df6-5511-bd75a0277e00/socialsharingimage)

3. In **Callback URL**, copy the **Kinde domain** value. It is a full HTTPS URL, for example `https://yourdomain.kinde.com/login/callback`.

   ![kinde authentication page showing the google social connection with the callback url](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/ac2ec324-3c03-4b69-d9f1-d40087432100/socialsharingimage)

   To show your own domain on the Google sign-in screen, turn on **Use custom domain instead** and copy that callback URL. See [Show your own domain on the Google sign-in screen](#show-your-own-domain-on-the-google-sign-in-screen).

   <Aside>

   If you use custom domains for more than one organization, copy each organization's callback. Add each URL in the Google client, and include `https://` on every URL.

   </Aside>

   Use the callback URL you copied when you configure the Google OAuth client in the following steps.

4. Select **Save**.

### 2. Create a Google Cloud project

Create a project for this sign-in so its settings stay separate from your other Google Cloud apps.

1. Sign in to the [Google Cloud console](https://console.cloud.google.com/). Your Google account needs 2-Step Verification turned on.
2. Select the project picker in the top bar, then select **New project**.

   ![select a new project button](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/1e3112f5-445e-4f56-7c02-4c9f53235300/socialsharingimage)

3. Enter a **Project name**, for example, your app or business name. Google generates a **Project ID** from the name. Select **Edit** to change the ID. The ID is fixed once the project is created.

   ![google cloud new project form](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/8d16f1be-55ad-4a57-d6d3-51faf0012100/socialsharingimage)

4. For **Parent resource**, keep **No organization** or select your organization, then select **Create**. It takes a few seconds to create the project.

5. In the notification that appears, select **Select Project**. Check that the project picker in the top bar shows your new project before you continue.

### 3. Set up Google Auth Platform

1. On your project welcome page, select **View all products**. This opens the All products page.

   ![google cloud project welcome page with view all products link](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/b1b1949d-de6b-4d15-9767-e8b86f1bad00/socialsharingimage)

2. On the All products page, select **Google Auth Platform**.

   ![google cloud all products page with Google auth platform link](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/66214b4f-2c34-498a-d6bc-d2cb41225200/socialsharingimage)

3. Because this is a new project, you will see **Google Auth Platform not configured yet**. Select **Get started**.

   ![google auth platform overview showing get started](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/3e5084f9-6b31-44c4-cfcc-b1f5163c5a00/socialsharingimage)

4. In **App Information**, complete the following, then select **Next**:
   - **App name**: enter the name users see when they sign in.
   - **User support email**: select a support email.

   ![google auth platform app information step](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/3eb01073-7139-487b-eb67-eebf4880e800/socialsharingimage)

5. In **Audience**, select **External**, then select **Next**.

   <Aside>

   Select **Internal** only if every user belongs to your Google Workspace organization.

   </Aside>

6. In **Contact Information**, enter the email addresses Google should use to contact you about the project. Select **Next**.
7. In **Finish**, select the **I agree to the Google API Services: User Data Policy** checkbox, then select **Continue**.
8. Select **Create**. A message confirms **OAuth configuration created!**

### 4. Add test users

New apps start in **Testing**. Only the test users you add can sign in. Google caps the app at **100** test users over its lifetime. The app can stay unverified while it is in **Testing**.

1. In **Google Auth Platform**, select **Audience**.
2. Under **Test users**, select **Add users**.
3. Enter the email addresses of the people who will test sign-in, then select **Save**.

   ![google auth platform audience page in testing](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/44ee7cc5-02d9-4014-c640-c309b4184a00/socialsharingimage)

Leave the app in **Testing** until you [publish it](#publish-the-app).

### 5. Create the OAuth client

1. In **Google Auth Platform**, select **Clients**, then select **Create client**.
2. For **Application type**, select **Web application**.
3. Enter a **Name** for the client, for example, `Kinde`. Users do not see this name.
4. Leave **Authorized JavaScript origins** empty for Kinde-hosted sign-in.
5. Under **Authorized redirect URIs**, select **Add URI** and enter each Kinde callback URL you copied, including `https://`. For example, `https://<your_kinde_subdomain>.kinde.com/login/callback`. If you use custom domains, also add each organization's callback URL, for example `https://auth.yourdomain.com/login/callback`.

   ![create oauth client form with web application and redirect uri](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/16f289df-46b7-4659-b9e8-d2601f68e400/socialsharingimage)

6. Select **Create**.
7. In the **OAuth client created** dialog, copy the **Client ID** and **Client secret**, or select **Download JSON**. Store them somewhere safe. Use these credentials when you configure the Google connection in Kinde.

   <Aside type="warning">

   Google shows the client secret only in this dialog. The **Client ID** stays visible under **Clients**.

   </Aside>

   ![oauth client created dialog with the client id and client secret](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/63fb534e-f886-43a2-b57e-75858bd8ab00/socialsharingimage)

8. Select **OK**.

<Aside>

It may take 5 minutes to a few hours for Google settings to take effect. If sign-in fails with a redirect error immediately after you create the client, wait and try again.

</Aside>

### 6. Add the credentials to Kinde

1. In Kinde, go to **Settings > Environment > Authentication**.
2. In **Social connections**, select **Configure** on the Google tile.
3. Under **Details**:
   - **Connection ID** is read-only.
   - **Connection name**: enter an internal name for this connection.
   - **External name**: enter the label for the hosted sign-in button. The default is **Google**.
4. Under **Provisioning**, keep **Email address trust** set to **Trust**. Google verifies email addresses. See [Trusting emails from providers](/authenticate/about-auth/identity-and-verification/#trusting-emails-from-providers) for how these options work.

   ![configure google connection dialog with trust selected for email address trust](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/bf1c6a8e-cddb-4f2f-21ce-c8ecc1edc300/socialsharingimage)

5. Under **Keys**, paste the **Client ID** and **Client secret** from Google. In production, these are your own app's credentials.
6. Under **Callback URL**, confirm the HTTPS callback URL matches the **Authorized redirect URI** you added in Google. To use a custom domain, turn on **Use custom domain instead**. See [Show your own domain on the Google sign-in screen](#show-your-own-domain-on-the-google-sign-in-screen).

   ![configure google connection dialog with client id, client secret, and callback url](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/cbd638a8-feb0-4b1e-cfa4-39ce8ebeaa00/socialsharingimage)

7. Under **Permissions**, leave **Email address** checked. Kinde adds the required basic profile permissions automatically.
8. Under **Applications**, turn on Google for each application that should use it. You can also manage connections under **Applications > [app] > Authentication**.
9. You can leave these settings at their defaults:
   - **Allow passkeys for users of this connection** is off. Turn it on to offer passkey setup after sign-in, including when passkeys are mandatory. See [Enable Passkeys to sign in users](/authenticate/authentication-methods/passkeys/).
   - Under **Advanced**, add [upstream params](/authenticate/auth-guides/pass-params-idp/) for Google. For example, `prompt=select_account` forces the Google account selector.
10. Select **Save**.

### 7. Publish the Google app

Move the app to **In production** when anyone with a Google account should be able to sign in. Until then, only the test users you added can sign in.

1. Complete **Branding** with the app name, user support email, and developer contact. **Publish app** stays unavailable until **Branding** is complete.
2. On the **Audience** page, select **Publish app**.

## Scopes (optional)

Adding scopes in **Data Access** is optional for basic Kinde sign-in. By default, no scopes are listed. Sign-in still works, because Kinde requests `openid`, `profile`, and `email`.

If you add scopes, go to **Data Access**, select **Add or remove scopes**, and use **Manually add scopes** with the full `https://` strings:

- `https://www.googleapis.com/auth/userinfo.email`
- `https://www.googleapis.com/auth/userinfo.profile`
- `openid`

![google auth platform data access page with the update selected scopes panel open](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/4a6e5a50-f5b9-43ef-b850-88ad3f514400/socialsharingimage)

## Show your own domain on the Google sign-in screen

By default, the Google sign-in screen shows the app name as **kinde.com**.

![google sign-in screen showing the app name as kinde.com](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/19e633fb-8100-4eef-6291-94d734203000/socialsharingimage)

If you want to change it to your own domain, follow these steps:

### Kinde configuration

1. Use a custom domain that is already **Provisioned** in Kinde. See [Use a custom domain with Kinde](/build/domains/pointing-your-domain/).
2. In the Google connection, under **Callback URL**, turn on **Use custom domain instead**, select the callback URL (for example `https://auth.yourdomain.com/login/callback`), and select **Save**.

   ![configure google connection dialog with use custom domain instead turned on](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/57380a51-6048-47b0-61f1-946b867bcb00/socialsharingimage)

### Google Cloud configuration

1. In the Google Cloud client, add that same custom domain callback URL you copied from Kinde as an **Authorized redirect URI**. You can keep the `kinde.com` callback as well.
2. In **Branding > Authorized domains**, add the custom domain's root, for example `yourdomain.com`, not the `auth.` hostname.
3. Wait for the settings to take effect. This can take 5 minutes to a few hours. Google may return **Error 400: redirect_uri_mismatch** shortly after you save. The error is often caused by that delay, so wait and retry before you change anything else.
4. Start the sign-in flow on the custom domain. Your app's Kinde domain, often `KINDE_ISSUER_URL`, must be the custom domain. See [Use a custom domain with Kinde](/build/domains/pointing-your-domain/).

The chooser then shows **"to continue to"** your domain, for example **yourdomain.com** when the callback is `https://auth.yourdomain.com/login/callback`. The developer info popup shows the app name as that domain.

![google account chooser showing to continue to a custom domain](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/193e70ed-d66e-49d1-521b-4c1e985fd000/socialsharingimage)

Google app's brand verification is optional. Complete it if you want the app name and logo on the Google screen. It requires a home page on a domain verified in Google Search Console, a privacy policy, and a logo. See [Manage OAuth App Branding](https://support.google.com/cloud/answer/15549049?hl=en). Basic Google sign-in works without brand verification.

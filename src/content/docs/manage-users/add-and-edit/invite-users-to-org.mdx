If you want to invite users to an organization from your own app, use the Kinde Management API. This guide covers the Management API endpoints for creating, listing, retrieving, and revoking invitations.

<Aside>

You can also invite users to an organization from the self-serve portal. See [Invite members from the portal](/build/self-service-portal/self-serve-portal-for-orgs/#invite-members-from-the-portal).

</Aside>

## What you need

- A [Kinde](https://kinde.com) account with **Admin** or **Engineer** permissions (sign up for free)
- A machine-to-machine (M2M) application with the Management API enabled and the following scopes enabled:
  - `create:organization_invites`
  - `read:organization_invites`
  - `delete:organization_invites`
  See the [quick start guide](/developer-tools/kinde-api/connect-to-kinde-api/)


## Enable invites in Kinde

### 1. Turn on invitations

Invitations are switched off by default. To switch them on:

1. Sign in to the Kinde dashboard. Go to **Settings > Environment > Policies**.
2. Scroll down to the **Invitations** section and switch on **Allow invitations**.

    ![allow invitations switch](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/6c49af0d-8b8f-484b-f40f-85963e8c0000/socialsharingimage)

3. Select the application from the dropdown that appears. Invitation links open in this application.
4. Select **Save**.

### 2. Set the Application login URI

The application you choose needs an **Application login URI**. Otherwise, invitation links are blocked and the invitee sees an error. To set this up:

1. Go to **Settings > Environment > Applications**, then select the **Customer identity** tab.
2. Select **View details** on the application tile you selected in the previous step. The **Details** page opens.
3. Scroll down to the **Callback URLs** section and enter the **Application login URI** for the application.
4. Select **Save**.


### 3. Allow sign-ups in the organization

The organization you're inviting people into also needs to accept sign-ups. Organizations don't accept sign-ups by default, so check this on any organization you're inviting people into. See [Manage user sign up to organizations](/build/organizations/allow-user-signup-org/).

<Aside>

If member invitations aren't available on your plan, the **Invitations** section doesn't appear on the **Policies** page and the invitation endpoints can't be used.

</Aside>

## API code snippets

### Invite a user

Send a `POST` request to the organization's invites endpoint with the person's `email` address and the `roles` they should get. Requires the `create:organization_invites` scope.

```bash
curl -X POST 'https://<your_kinde_domain>/api/v1/organization/org_1ccfb819462/invites' \
  -H 'Authorization: Bearer <your_access_token>' \
  -H 'Content-Type: application/json' \
  -d '{
    "email": "user@example.com",
    "first_name": "John",
    "last_name": "Doe",
    "roles": ["admin"],
    "send_email": true
  }'
```

#### Invitation constraints

- At least one role is required.
- In the request body, `roles` must be a JSON array of role **keys**, not role names — a bare string is rejected (`ROLES_INVALID_FORMAT`).
- If a role requires an assignment permission, the caller — or the user the token represents — must hold that permission. 

    <Aside type="upgrade">

    Assigning roles other than `owner` and `admin` requires a [Kinde paid plan](https://kinde.com/pricing).

    </Aside>

- `email` is limited to 254 characters.
- `first_name` and `last_name` are limited to 64 characters each.


<Aside type="warning">

`send_email` defaults to `false`. If you leave it out, Kinde creates the invitation but doesn't email anyone — it's up to you to deliver the `invite_link` from the response. Set `send_email` to `true` if you want Kinde to send the invitation email.

The invitation email uses your sender, logo, and colours, but the wording is fixed. It isn't editable in the email content editor, isn't translatable, and the subject currently mentions Kinde. Use `send_email: false` and deliver `invite_link` yourself if you need full control of the copy.

</Aside>

#### Response

The invitation details are returned under an `invite` key. In the response, `roles` is an array of objects rather than an array of keys.

```json title="Sample response"
{
  "code": "INVITATION_CREATED",
  "message": "Invitation created",
  "invite": {
    "id": "inv_abc123def456",
    "code": "inv_abc123def456",
    "email": "user@example.com",
    "first_name": "John",
    "last_name": "Doe",
    "full_name": "John Doe",
    "created_on": "2024-11-18T13:32:03+11",
    "is_sent": true,
    "accepted_on": null,
    "roles": [
      {
        "key": "admin",
        "name": "Administrator"
      }
    ],
    "is_revoked": false,
    "invite_link": "https://<your_kinde_domain>/team_invitation?code=inv_abc123def456"
  }
}
```

<Aside type="warning">

A `201` doesn't guarantee an email went out. Check `is_sent` on the response when you pass `send_email: true`. `is_sent: true` means the email was queued for delivery, not that it was delivered.

There are no invitation webhook events. The reliable signal that someone joined is `user.created` when a new account is created, `user.updated` when an existing user is added to the organization, or `accepted_on` being set on a later GET. See [About webhooks](/integrate/webhooks/about-webhooks/).

</Aside>

Use `invite_link` when you want to deliver the invitation from your own product — in your own email template, in an in-app notification, or as a link an admin can copy and share.

See [Create organization invite](/kinde-apis/management#tag/organizations/post/api/v1/organization/{org_code}/invites) for the full request and response reference.

### List invitations for an organization

Send a `GET` request to the organization's invites endpoint to list all invitations. Requires the `read:organization_invites` scope.

```bash
curl 'https://<your_kinde_domain>/api/v1/organization/org_1ccfb819462/invites' \
  -H 'Authorization: Bearer <your_access_token>'
```

By default, you get pending invitations only — anything already accepted or revoked is left out. Add `include_accepted=true` or `include_revoked=true` to include those results.

You can also sort and page through the list:

- `sort` — one of `created_on_asc`, `created_on_desc`, `email_asc`, `email_desc`, `name_asc`, or `name_desc`.
- `page_size` — number of results per page. Defaults to 10.
- `next_token` — pass the `next_token` returned with a page to get the next set of results.

See [Get organization invites](/kinde-apis/management#tag/organizations/get/api/v1/organization/{org_code}/invites).

### Get a single invitation

To check the status of one invitation, request it by its code. The response tells you whether the invitation was queued (`is_sent`), accepted (`accepted_on`), or revoked (`is_revoked`).

Use this `GET` request:

```bash
curl 'https://<your_kinde_domain>/api/v1/organization/org_1ccfb819462/invites/inv_abc123def456' \
  -H 'Authorization: Bearer <your_access_token>'
```

There are no invitation webhook events. The signal that someone joined is `user.created` when a new account is created, `user.updated` when an existing user is added to the organization, or `accepted_on` being set on a later GET. See [About webhooks](/integrate/webhooks/about-webhooks/).

See [Get organization invite](/kinde-apis/management#tag/organizations/get/api/v1/organization/{org_code}/invites/{invite_code}).

### Delete an invitation

Deleting an invitation marks it as `revoked` and prevents it from being accepted. Invitations don't expire automatically — they stay valid until they're accepted or revoked.

Use this `DELETE` request:

```bash
curl -X DELETE 'https://<your_kinde_domain>/api/v1/organization/org_1ccfb819462/invites/inv_abc123def456' \
  -H 'Authorization: Bearer <your_access_token>'
```

Anyone who opens a revoked invitation link sees an expired-invitation message, not a revoked-invitation message.

<Aside>

There's no resend endpoint. To send a fresh invitation, revoke the existing one and create a new one.

</Aside>

See [Delete organization invite](/kinde-apis/management#tag/organizations/delete/api/v1/organization/{org_code}/invites/{invite_code}).

## Rate limits

Invitations are limited per organization:

- **100 invitations** per rolling 24-hour window. The error code is `INVITE_LIMIT_DAILY_REACHED`.
- **500 outstanding invitations** at any time. Outstanding means neither accepted nor revoked. The error code is `INVITE_LIMIT_ACTIVE_REACHED`.

Accepting or revoking an invitation frees up capacity against the outstanding limit. These limits matter most if you're bulk-inviting from your own portal.

## Send the invitation email from your own domain

If you set `send_email` to `true`, Kinde chooses the sender in this order:

1. The organization's sender name and email, if you've set them for that organization. An organization-specific sender address also needs a [custom SMTP email provider](/get-started/connect/customize-email-sender/) with provider details configured for that address. See [Customize email sender for an organization](/build/organizations/email-sender-organization/).
2. Your environment's configured email provider. See [Customize email sender](/get-started/connect/customize-email-sender/).
3. Kinde's default sender.

The invitation email uses your branding — sender name and address, logo, and colours. The wording is fixed. It isn't editable in the email content editor, isn't translatable, and the subject currently mentions Kinde. If you need full control of the copy, set `send_email` to `false` and deliver the `invite_link` yourself.

## What the invited person sees

When someone opens their invitation link, they land on the sign-up screen for your invite application, with their details prefilled and their email address locked. An invitation bypasses the environment-level **Allow self sign-up** setting, so you can run an invitation-only product. The organization still needs to accept sign-ups. If it doesn't, invited users are blocked when they try to accept. Organizations don't accept sign-ups by default, so check this on any organization you're inviting people into. See [Manage user sign up to organizations](/build/organizations/allow-user-signup-org/).

Once they sign up, they join the organization with the roles from the invitation, plus any roles that are automatically assigned to new members of that organization.

For the full experience, including the messages shown when an invitation can't be used, see [Invited user sign-up experience](/authenticate/custom-configurations/invited-user-experience/).

## Errors

If a create request fails, the response includes a `code` you can switch on.

| Code                              | Means                                                            |
| --------------------------------- | ---------------------------------------------------------------- |
| `FEATURE_DISABLED`                | **Allow invitations** is switched off for the environment        |
| `CODE_IS_REQUIRED`                | No organization code supplied                                    |
| `ORGANIZATION_INVALID`            | The organization code doesn't match an organization              |
| `ORGANIZATION_DIRECTORY_PROVIDED` | The organization is managed by directory sync                    |
| `EMAIL_REQUIRED`                  | No email address supplied                                        |
| `EMAIL_INVALID`                   | The email address isn't valid                                    |
| `EMAIL_TOO_LONG`                  | Email address is over 254 characters                             |
| `FIRST_NAME_TOO_LONG`             | First name is over 64 characters                                 |
| `LAST_NAME_TOO_LONG`              | Last name is over 64 characters                                  |
| `EMAIL_ALREADY_IN_USE`            | That email already belongs to a member of the organization       |
| `EMAIL_ALREADY_INVITED`           | That email already has a pending invitation for the organization |
| `ROLES_REQUIRED`                  | No roles supplied — at least one is required                     |
| `INVALID_ROLES`                   | One or more role keys don't exist                                |
| `ROLES_INVALID_FORMAT`            | `roles` wasn't a JSON array of role-key strings                  |
| `INVITE_LIMIT_DAILY_REACHED`      | See [Rate limits](#rate-limits)                                  |
| `INVITE_LIMIT_ACTIVE_REACHED`     | See [Rate limits](#rate-limits)                                  |

Organizations managed by directory sync return `ORGANIZATION_DIRECTORY_PROVIDED`. Add the user in your identity provider instead and let the change sync through.

People who are already members return `EMAIL_ALREADY_IN_USE`. People who already have a pending invitation return `EMAIL_ALREADY_INVITED`. Revoke the existing invitation first if you need to change the roles attached to it.

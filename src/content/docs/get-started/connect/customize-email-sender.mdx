You can configure Kinde to send emails from your preferred email provider. Users then receive those emails from your business address.

A custom sender also gives you more control over deliverability, analytics, tracking, scalability, and compliance.

## Custom email provider requirements

Kinde sends authentication emails through any SMTP provider that supports:

- Username and password sign-in
- TLS encryption

You can connect only one provider at a time. Set up the custom sender before you make the environment live.

Enter the server, port, username, and password from your provider. Popular choices include Resend, Mailgun, Groundmail, SendGrid, Mailchimp, Postmark, and MailerSend.

### Emails sent from your address

When you set your own provider details, Kinde sends these emails from your address:

- Sign-up and sign-in emails
- One-time passcode (OTP) emails
- Password reset codes

If you do not set this up, these emails come from `no-reply@kinde.com`.

### Emails sent from Kinde

Kinde still sends these emails, even when you use a custom sender:

- Invitations to join the business team, when you add a team member manually or through the API
- Warnings and notifications about data exports

## Configure email sender

1. In Kinde, go to **Settings > Environment > Messaging > Email Sender**.
2. Enter a **Sender name**. This is usually your business name, or a specific person's name.
3. Enable the **Use custom sender** switch. The SMTP details section opens.

   ![Email Sender page with the Use custom sender switch turned on](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/576b53fa-35d0-4747-dc0d-1fc9f6dda600/socialsharingimage)

4. Enter the **Sender email**. This is the address users receive email from. Use an address on a domain verified with your email provider. Resend, Mailgun, and Groundmail require domain verification.
5. Enter the SMTP details from your email provider:

   - Server address - for example, `yourbusiness.smtp.providername.com`
   - Port - use the port your provider recommends
   - Username and password - your provider's SMTP sign-in details

   ![SMTP settings fields on the Kinde Email Sender page](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/955a1ef1-f101-44b5-14c0-df04f6535e00/socialsharingimage)

6. Select **Send test email**. Kinde sends the test to the email address you are signed in with.
7. If the test succeeds, select **Save**.
8. If the test fails, check the SMTP details in step 5 and send the test again. If it still fails, see the troubleshooting section of your provider's guide below, or [External resources](#external-resources).

For provider-specific steps, see:

- [Resend](/integrate/third-party-tools/kinde-resend-custom-smtp/)
- [Mailgun](/integrate/third-party-tools/kinde-mailgun-email-delivery/)
- [Groundmail](/integrate/third-party-tools/kinde-groundmail-custom-smtp/)

<Aside>

Users who are signing in when you enable this setting do not receive emails from the new address until they start a new authenticated session.

</Aside>

## Edit email sender

Test SMTP changes in a non-production environment first.

1. In Kinde, go to **Settings > Environment > Messaging > Email Sender**.
2. Update the details you want to change.
3. Select **Send test email**. Kinde sends the test to the email address you are signed in with.
4. If the test succeeds, select **Save**.

## Reset email sender

Only do this if the environment is not live.

1. In Kinde, go to **Settings > Environment > Messaging > Email Sender**.
2. Disable the **Use custom sender** switch. This switches back to the default Kinde email address and removes the SMTP details.
3. Select **Save**.

## Email sending alerts

If your SMTP provider starts rejecting emails from Kinde, for example because the password changed, Kinde shows an alert in the dashboard so you can fix the problem before users miss sign-in codes and password reset emails.

### Error banners

When an email fails to send through your custom SMTP details:

- **Home page** - An **Email sending issue** banner appears. Select **View email settings** to open the Email Sender page.

  ![kinde home dashboard with an email sending issue banner and a view email settings link](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/d1d65644-e1b0-4b58-af00-b9abb98a7a00/socialsharingimage)

- **Home page (multiple issues)** - If other issues are present at the same time, a **Multiple issues detected** banner appears instead, with a link to the status page.

  ![kinde home dashboard with a multiple issues detected banner and a view status page link](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/ab7c12e6-7f0c-466c-a0a6-578890194700/socialsharingimage)

- **Status page** - Select **View status page** on the **Multiple issues detected** banner. The **Email sender** card shows an error when custom SMTP sending has failed.

  ![kinde status page with a multiple issues detected banner and an email sender card showing issue detected](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/d5434817-81c4-40ab-9f01-248cfc76f800/socialsharingimage)

- **Email Sender page** - A banner at the top of the page shows the latest sending error from the last failed attempt.

  ![email sender settings page with an error banner showing the latest sending error from the last failed send attempt](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/fcf76338-1167-4b2a-c317-066a65aa6600/socialsharingimage)

Kinde keeps only the most recent failure. A new failure replaces the error in the banner.

### What triggers an alert

Kinde shows an alert when your SMTP server rejects an email because of a problem with your sender settings, for example:

- The username or password is wrong
- Kinde can't connect to the server or port
- The server rejects your sender email address
- The server refuses to relay the email or blocks it for policy reasons

Problems with an individual recipient, such as an email address that doesn't exist or a full mailbox, don't trigger an alert. Those failures do not mean your settings are wrong.

Kinde shows these alerts only when you use a custom SMTP sender. If you use Kinde's default email sender, Kinde monitors delivery for you.

### Clear an alert

The alert clears automatically when:

- An email sends successfully through your SMTP server.
- You save your email sender details.
- You send a successful test email with the details that are already saved.

If you test new details, save them as well. Kinde keeps using the saved details for real emails until you do.

To fix the problem:

1. In Kinde, go to **Settings > Environment > Messaging > Email Sender**.
2. Read the latest sending error in the banner at the top of the page.
3. Check your **Sender email** and SMTP details, and update the password if it has changed at your provider.
4. Select **Send test email**.
5. If the test succeeds, select **Save**. The alert clears.

If the error continues, see the troubleshooting section of the [Resend](/integrate/third-party-tools/kinde-resend-custom-smtp/#troubleshooting), [Mailgun](/integrate/third-party-tools/kinde-mailgun-email-delivery/#troubleshooting), or [Groundmail](/integrate/third-party-tools/kinde-groundmail-custom-smtp/#troubleshooting) guide, or [External resources](#external-resources).

## Best practices

- Test SMTP changes in a non-production environment first. See [Environments in Kinde](/build/environments/environments/).
- Use a reputable email provider with a low spam score.
- Use TLS to protect the connection.
- Use a strong password for your email provider account.

## Email provider limitations

Some email providers have limitations on the number of emails you can send per day or month (such as Microsoft 365). Check your provider's limits before you start using a custom sender.

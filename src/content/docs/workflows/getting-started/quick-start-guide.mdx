Follow this guide to set up your project and create your first workflow.

## What you need

- A [Kinde](https://app.kinde.com/register) account with [an application set up](/get-started/guides/byo-code/) (sign up for free)
- A [GitHub](https://github.com/) account to host your code (sign up for free)

## Quickstart (using the base template)

### 1. Clone the base template

1. Sign in to your GitHub account and open the [Kinde base workflow template](https://github.com/kinde-starter-kits/workflow-base-template).
2. Select the green **Use this template** button, then select **Create a new repository**.
3. Enter an easily identifiable name for your repository (for example, `kinde-wf-base-template`).
4. Clone the repository to your local machine using your preferred method (for example, Git CLI or GitHub Desktop).

The base template contains a basic workflow that writes `Hello world` to runtime logs when a user authenticates.

### 2. Connect Git repo to Kinde

1. Sign in to your Kinde account and go to **Settings > Environment > Git repo**.
2. Select **Connect GitHub**.
3. Follow the instructions to connect your GitHub account to Kinde.
4. Select the repository you created in the previous step, then select **Next**.
5. Select the branch (for example, `main`) and select **Save**.

    Kinde will automatically sync the code and create a new workflow for you.
6. Go to **Kinde home > Workflows** to view your new workflow. You should see a new workflow called `Workflow 1`.

    ![Workflow 1 base template](https://imagedelivery.net/skPPZTHzSlcslvHjesZQcQ/ae778ce4-bd2f-45ba-5de5-3c21d9b51b00/socialsharingimage)
7. Select the workflow to see the details and deployments.
8. Select **Runtime logs** to view the logs for the workflow. This should currently be empty.

### 3. Test the workflow

[Run your Kinde application](/get-started/guides/byo-code/) and sign in. This triggers the workflow and creates a new runtime log entry.

1. Open **Runtime logs** for the workflow again (refresh the page if the list does not update).
2. Select the new log entry to see **Hello world** in the output (see sample below).

    ```text title="Workflow sample output"
    Post-authentication trigger fired
    Workflow found
    JavaScript execution started…
    Info Hello world
    🎉 Workflow completed in 0.7ms
    ```

## Manually create a workflow

Prefer to scaffold the project yourself instead of using the template? Follow these steps to recreate the same [base template](https://github.com/kinde-starter-kits/workflow-base-template) setup from scratch.

### 1. Create the project and folder structure

1. Create a new directory for your workflows repository and move into it:

    ```bash
    mkdir kinde-workflows && cd kinde-workflows
    ```

2. Initialize a Git repository (skip this if you already have one):

    ```bash
    git init
    ```

3. Create the folder structure Kinde expects, including a folder for this workflow:

    ```text title="Kinde workflow folder structure"
    kindeSrc/
      └── environment/
        └── workflows/
          └── postUserAuthentication/
    ```

    ```bash
    mkdir -p kindeSrc/environment/workflows/postUserAuthentication
    ```

### 2. Add configuration files

1. Create `kinde.json` in the project root. This tells Kinde where to discover your workflow code:

    ```bash
    cat > kinde.json << 'EOF'
    {
      "rootDir": "kindeSrc",
      "version": "2025-11-11",
      "integrations": { "npm": { "enabled": true } }
    }
    EOF
    ```

2. Initialize a `package.json` file:

    ```bash
    npm init -y
    ```

3. (Optional) Add the [Kinde infrastructure package](/workflows/getting-started/infrastructure-package/) if you want workflow types and methods during development:

    ```bash
    npm i @kinde/infrastructure
    ```

4. (Optional) Add a `tsconfig.json` if you use TypeScript:

    ```bash
    cat > tsconfig.json << 'EOF'
    {
      "compilerOptions": {
        "target": "ES2020",
        "module": "ESNext",
        "moduleResolution": "Node",
        "strict": true,
        "esModuleInterop": true,
        "skipLibCheck": true
      },
      "include": ["**/*.ts"]
    }
    EOF
    ```

### 3. Create the workflow file

1. Create a workflow file. The filename must end with `Workflow` (for example, `Workflow.ts` or `postAuthWorkflow.ts`). See [Workflow files](/workflows/getting-started/workflow-files/).

    ```bash
    touch kindeSrc/environment/workflows/postUserAuthentication/Workflow.ts
    ```

2. Add the following code. This matches the base template: it runs on the [post-authentication](/workflows/example-workflows/workflow-user-post-auth/) trigger and logs `Hello world`.

    ```ts title="kindeSrc/environment/workflows/postUserAuthentication/Workflow.ts"
    import {
      onPostAuthenticationEvent,
      WorkflowSettings,
      WorkflowTrigger,
    } from "@kinde/infrastructure";

    // The setting for this workflow
    export const workflowSettings: WorkflowSettings = {
      id: "onPostUserAuthentication",
      name: "Post user authentication workflow",
      trigger: WorkflowTrigger.PostAuthentication,
    };

    // The workflow code to be executed when the event is triggered
    export default async function Workflow(event: onPostAuthenticationEvent) {
      console.log("Hello world");
    }
    ```

3. Commit your changes and push them to a GitHub repository.

    ```bash
    git add .
    git commit -m "Initial kinde workflow commit"
    git push
    ```

    <Aside>
    You must have a GitHub repository and a remote `origin` set before you can push. See GitHub's guide on [adding locally hosted code to GitHub](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github).
    </Aside>

### 4. Connect Git repo to Kinde

Follow [step 2 in Quickstart](#2-connect-git-repo-to-kinde) to connect your repository and confirm the workflow appears under **Workflows**.

### 5. Test the workflow

Follow [step 3 in Quickstart](#3-test-the-workflow): sign in to your app, then check **Runtime logs** for the `Hello world` output.

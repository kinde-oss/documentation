You can fetch third-party data in your workflows and use it in your logic.

## What you need

- A [Kinde](https://app.kinde.com/register) account (Sign up for free)
- A workflow Git repository connected to your Kinde account (follow the [quick start guide](/workflows/getting-started/quick-start-guide/))
- A third-party data source such as a database or API

## About the Kinde fetch binding

Workflows run in a secure, restricted JavaScript runtime—not Node.js. Network access is off by default. The [`kinde.fetch`](/workflows/bindings/fetch-binding/) binding is how you opt in to outbound HTTP so your workflow can call external APIs (including the Kinde Management API).

It is not the same as the browser or Node `fetch` API. Use the Kinde helper from `@kinde/infrastructure` (or the low-level `kinde.fetch` API), and declare the binding in `workflowSettings` before you call it.

What you get with `kinde.fetch`:

- Outbound HTTP from the workflow (typically GET and POST)
- A `responseFormat` option (for example `"json"`) so the response is parsed for you
- A typed helper that returns `{ data }` when you import `fetch` from `@kinde/infrastructure`
- Requires the [`url`](/workflows/bindings/url-binding/) binding (used under the hood by the helper)

For sensitive request bodies (such as passwords), use [`kinde.secureFetch`](/workflows/bindings/secure-fetch-binding/) instead so the payload is encrypted.

Minimal example:

```typescript
import { fetch } from "@kinde/infrastructure";

// In workflowSettings.bindings: { "kinde.fetch": {}, url: {} }

const { data } = await fetch("https://api.example.com/status", {
  method: "GET",
  responseFormat: "json",
  headers: {
    "Content-Type": "application/json",
  },
});

console.log(data);
```

## Fetch third-party data

1. Import the `fetch` helper from `@kinde/infrastructure`:
    ```typescript
    import { fetch } from "@kinde/infrastructure";
    ```

2. Add `kinde.fetch` and `url` bindings to the workflow settings:
    ```typescript
    bindings: {
      "kinde.fetch": {},
      url: {},
    },
    ```

3. Call `fetch` to get the third-party data, and check that the response is OK before using it:

    ```typescript 
    const { data: userData } = await fetch(`https://my-website.com/api/user/some-user-id`, {
        method: "GET",
        responseFormat: "json",
        headers: {
          "Content-Type": "application/json",
        },
      });

    if (!userData) {
      console.error("Failed to fetch user data");
      return;
    }

    // use the userData as needed
    console.log(userData);
    ```

    The infrastructure `fetch` helper returns `{ data }` only. To check HTTP status (for example `response.ok`), call the low-level `kinde.fetch` API instead—see the full example below.

4. Combine the fetched data with your workflow logic as needed.

Full `Workflow.ts` file example:

    ```typescript
    import {
      onUserTokenGeneratedEvent,
      accessTokenCustomClaims,
      WorkflowSettings,
      WorkflowTrigger,
    } from "@kinde/infrastructure";

    export const workflowSettings: WorkflowSettings = {
      id: "addThirdPartyDataToAccessToken",
      name: "Add third party data to access token",
      trigger: WorkflowTrigger.UserTokenGeneration,
      bindings: {
        "kinde.accessToken": {},
        "kinde.fetch": {},
        url: {},
      },
    };

    export default async function FetchThirdPartyDataWorkflow(
      event: onUserTokenGeneratedEvent
    ) {
      const accessToken = accessTokenCustomClaims<{
        lifetime_subscriber: boolean;
      }>();
      
      const loggedInUserId = event.context.user.id;
      const response = await kinde.fetch(`https://my-website.com/api/user/${loggedInUserId}`, {
        method: "GET",
        responseFormat: "json",
        headers: {
          "Content-Type": "application/json",
        },
      });

      if (!response.ok) {
        console.error("Failed to fetch user data");
        return;
      }
      
      accessToken.lifetime_subscriber = response.json?.lifetime_subscriber || false;
    }
    ```

    The code fetches the user data from the third-party data source and stores it in the access token. If the request is not OK, it logs the failure and exits without setting the claim. **GET** is appropriate for a read-only lookup by user ID, matching the [kinde.fetch](/workflows/bindings/fetch-binding/) examples.

## Use the secure fetch

If you need to send sensitive data in the request body to a backend you control, use the `kinde.secureFetch` binding instead of `kinde.fetch`.

1. Create an encryption key in Kinde. Go to **Workflow > Encryption keys** and select **Add encryption key**.

2. Add `kinde.secureFetch` and `url` bindings to the workflow settings:
    ```typescript
    bindings: {
      "kinde.secureFetch": {},
      url: {},
    },
    ```

3. Call the low-level `kinde.secureFetch` API and check that the response is OK before using it:

    ```typescript
    const response = await kinde.secureFetch(`https://my-website.com/api/user/some-user-id`, {
        method: "POST",
        responseFormat: "json",
        headers: {
          "Content-Type": "application/json",
        },
        body: {
          name: "John Doe",
        },
      });

    if (!response.ok) {
      console.error("Failed to fetch user data");
      return;
    }
    ```

4. Decode the response body in your backend using the encryption key. Learn more about the [encryption key](/workflows/manage-workflows/encrypt-decrypt-workflows/).

Full `Workflow.ts` file example:
```typescript
import {
  onUserTokenGeneratedEvent,
  accessTokenCustomClaims,
  WorkflowSettings,
  WorkflowTrigger,
} from "@kinde/infrastructure";

export const workflowSettings: WorkflowSettings = {
  id: "addThirdPartyDataToAccessToken",
  name: "Add third party data to access token",
  trigger: WorkflowTrigger.UserTokenGeneration,
  bindings: {
    "kinde.accessToken": {},
    "kinde.secureFetch": {},
    url: {},
  },
};

export default async function FetchThirdPartyDataWorkflow(
  event: onUserTokenGeneratedEvent
) {
  const accessToken = accessTokenCustomClaims<{
    lifetime_subscriber: boolean;
  }>();

  const loggedInUserId = event.context.user.id;
  const response = await kinde.secureFetch(`https://my-website.com/api/user/${loggedInUserId}`, {
    method: "POST",
    responseFormat: "json",
    headers: {
      "Content-Type": "application/json",
    },
    body: {
      name: "John Doe",
    },
  });

  if (!response.ok) {
    console.error("Failed to fetch user data");
    return;
  }

  accessToken.lifetime_subscriber = response.json?.lifetime_subscriber || false;
}
```

## Use environment variables

Store sensitive or repetitive values in environment variables instead of hardcoding them in the workflow.

1. Go to **Kinde > Settings > Data management > Env variables** and add any environment variables you need in your workflow (for example, `API_URL` or `API_KEY`). Learn more about [environment variables and secrets](/workflows/configuration/environment-variables-and-secrets/).

2. Add the `kinde.env` binding to the workflow settings:
    ```typescript
    bindings: {
      "kinde.env": {},
    },
    ```

3. Access environment variables in the workflow with the helper method:

    ```typescript
    // import the helper method
    import { getEnvironmentVariable } from "@kinde/infrastructure";

    // access within the workflow
    const apiKey = getEnvironmentVariable("API_KEY")?.value;
    ```

Full `Workflow.ts` file example:

    ```typescript
    import {
      onUserTokenGeneratedEvent,
      accessTokenCustomClaims,
      WorkflowSettings,
      WorkflowTrigger,
      getEnvironmentVariable,
    } from "@kinde/infrastructure";

    export const workflowSettings: WorkflowSettings = {
      id: "addThirdPartyDataUsingEnvs",
      name: "Add third party data to access token using environment variables",
      trigger: WorkflowTrigger.UserTokenGeneration,
      bindings: {
        "kinde.accessToken": {},
        "kinde.fetch": {},
        "kinde.env": {},
        url: {},
      },
    };

    export default async function FetchThirdPartyDataWorkflow(
      event: onUserTokenGeneratedEvent
    ) {
      const accessToken = accessTokenCustomClaims<{
        lifetime_subscriber: boolean;
      }>();

      const apiKey = getEnvironmentVariable("API_KEY")?.value;
      if (!apiKey) {
        console.error("API_KEY environment variable is not set");
        return;
      }
      
      const loggedInUserId = event.context.user.id;
      const response = await kinde.fetch(`https://my-website.com/api/user/${loggedInUserId}`, {
        method: "GET",
        responseFormat: "json",
        headers: {
          "Authorization": `Bearer ${apiKey}`,
          "Content-Type": "application/json",
        },
      });

      if (!response.ok) {
        console.error("Failed to fetch user data");
        return;
      }
      
      accessToken.lifetime_subscriber = response.json?.lifetime_subscriber || false;
    }
    ```

Use workflows to customize access tokens, ID tokens, and M2M tokens.

## What you need

- A [Kinde](https://app.kinde.com/register) account (Sign up for free)
- A workflow Git repository connected to your Kinde account (follow the [quick start guide](/workflows/getting-started/quick-start-guide/))

## Customize the access token

1. Add the access token binding to the workflow settings:

    ```typescript
    bindings: {
      "kinde.accessToken": {}
    },
    ```

2. Use the `UserTokenGeneration` trigger (alias for [`user:token_generation`](/workflows/example-workflows/user-token-generation/)):

    ```typescript
    trigger: WorkflowTrigger.UserTokenGeneration,
    ```

3. Define the custom claim and set its value:

    ```typescript
    const accessToken = accessTokenCustomClaims<{
      companyName: string,
    }>()
    
    accessToken.companyName = "Acme Inc."
    ```

Full `Workflow.ts` file example:

    ```typescript
    // Workflow.ts
    import {
      onUserTokenGeneratedEvent,
      WorkflowSettings,
      WorkflowTrigger,
      accessTokenCustomClaims,
    } from "@kinde/infrastructure";

    // The setting for this workflow
    export const workflowSettings: WorkflowSettings = {
      id: "addCustomClaimWorkflow",
      name: "Add Custom Claim Workflow",
      trigger: WorkflowTrigger.UserTokenGeneration,
      failurePolicy: {
        action: "stop",
      },
      bindings: {
        "kinde.accessToken": {}, // required to modify access token claims
        url: {}, // required for URL parameters
      },
    };

    // The workflow code to be executed when the event is triggered
    export default async function Workflow(event: onUserTokenGeneratedEvent) {
      const accessToken = accessTokenCustomClaims<{
        companyName: string,
      }>()

      accessToken.companyName = "Acme Inc."
    }
    ```

This code adds the `companyName` claim to the access token with the value `Acme Inc.`.

### Remove `permissions` and `feature_flags` claims from the access token

To remove claims from the access token, set them to an empty array or object:

```typescript
const accessToken = accessTokenCustomClaims<{
  permissions: string[],
  feature_flags: Record<string, unknown>,
}>()

accessToken.permissions = []
accessToken.feature_flags = {}
```

Full `Workflow.ts` file example:


    ```typescript
    // Workflow.ts
    import {
      onUserTokenGeneratedEvent,
      WorkflowSettings,
      WorkflowTrigger,
      accessTokenCustomClaims,
    } from "@kinde/infrastructure";

    // The setting for this workflow
    export const workflowSettings: WorkflowSettings = {
      id: "removeClaimWorkflow",
      name: "Remove Claim Workflow",
      trigger: WorkflowTrigger.UserTokenGeneration,
      failurePolicy: {
        action: "stop",
      },
      bindings: {
        "kinde.accessToken": {}, // required to modify access token claims
        url: {}, // required for URL parameters
      },
    };

    // The workflow code to be executed when the event is triggered
    export default async function Workflow(event: onUserTokenGeneratedEvent) {
      const accessToken = accessTokenCustomClaims<{
        permissions: string[],
        feature_flags: Record<string, unknown>,
      }>()

      accessToken.permissions = []
      accessToken.feature_flags = {}
    }
    ```

This code replaces `permissions` with an empty array and `feature_flags` with an empty object. This reduces the size of access tokens used in API calls.

See the available access token claims in [about access tokens](/build/tokens/about-access-tokens/). You may not be able to remove every default claim. See [prohibited claims](#prohibited-claims).

## Customize the ID token

1. Add the ID token binding to the workflow settings:

    ```typescript
    bindings: {
      "kinde.idToken": {}
    },
    ```

2. Use the `UserTokenGeneration` trigger (alias for [`user:token_generation`](/workflows/example-workflows/user-token-generation/)):

    ```typescript
    trigger: WorkflowTrigger.UserTokenGeneration,
    ```

3. Define the custom claim and set its value:

    ```typescript
    const idToken = idTokenCustomClaims<{
      house: string,
      name: string,
    }>()

    idToken.house = "Gryffindor"
    idToken.name = "Harry Potter"
    ```

Full `Workflow.ts` file example:

    ```typescript
    // Workflow.ts
    import {
      onUserTokenGeneratedEvent,
      WorkflowSettings,
      WorkflowTrigger,
      idTokenCustomClaims,
    } from "@kinde/infrastructure";

    // The setting for this workflow
    export const workflowSettings: WorkflowSettings = {
      id: "customIdTokenClaimsWorkflow",
      name: "Custom ID Token Claims Workflow",
      trigger: WorkflowTrigger.UserTokenGeneration,
      failurePolicy: {
        action: "stop",
      },
      bindings: {
        "kinde.idToken": {}, // required to modify ID token claims
        url: {}, // required for URL parameters
      },
    };

    // The workflow code to be executed when the event is triggered
    export default async function Workflow(event: onUserTokenGeneratedEvent) {
      const idToken = idTokenCustomClaims<{
        house: string,
        name: string,
      }>()

      idToken.house = "Gryffindor"
      idToken.name = "Harry Potter"
    }
    ```

This code adds a custom `house` claim to the ID token and updates the `name` claim.

See the available ID token claims in [about ID tokens](/build/tokens/about-id-tokens/). You may not be able to modify every default claim. See [prohibited claims](#prohibited-claims).

## Customize the M2M token

1. Add the M2M token binding to the workflow settings:

    ```typescript
    bindings: {
      "kinde.m2mToken": {}
    },
    ```

2. Use the `M2MTokenGeneration` trigger (alias for [`m2m:token_generation`](/workflows/example-workflows/m2m-token-generation-workflow/)):

    ```typescript
    trigger: WorkflowTrigger.M2MTokenGeneration,
    ```

3. Define the custom claim and set its value:

    ```typescript
    const m2mToken = m2mTokenClaims<{
        name: string
    }>()

    m2mToken.name = "Agent Smith"
    ```

Full `Workflow.ts` file example:

    ```typescript
    import {
      onM2MTokenGeneratedEvent,
      WorkflowSettings,
      WorkflowTrigger,
      m2mTokenClaims,
    } from "@kinde/infrastructure"
    
    export const workflowSettings: WorkflowSettings = {
      id: "m2mTokenGeneration",
      name: "M2M custom claims",
      failurePolicy: {
        action: "stop",
      },
      trigger: WorkflowTrigger.M2MTokenGeneration,
      bindings: {
        "kinde.m2mToken": {}
        url: {}, // required for URL parameters
      },
    }
    
    export default async function Workflow(event: onM2MTokenGeneratedEvent) {
      // set up types for the custom claims
      const m2mToken = m2mTokenClaims<{
        name: string
      }>()
    
      // Use the data to set the custom claim on the M2M token
      m2mToken.name = "Agent Smith"
    }
    ```

This code adds the `name` claim to the M2M token with the value `Agent Smith`.

You may not be able to modify every default claim. See [prohibited claims](#prohibited-claims).

## Glossary

### Required bindings

Declare the token binding that matches the JWT you are modifying:

- `kinde.accessToken`: required to modify access token claims
- `kinde.idToken`: required to modify ID token claims
- `kinde.m2mToken`: required to modify M2M token claims

The workflow examples on this page also declare the native `url` binding (for URL parameters).

### Prohibited claims

You cannot modify the following token claims:

**Common prohibited claims:**

- `azp`
- `exp`
- `iat`
- `iss`
- `nbf`
- `sid`
- `sub`
- `act`
- `aud`

**Access token prohibited claims:**

- `jti`
- `scp`

**ID token prohibited claims:**

- `auth_time`
- `jti`
- `updated_at`
- `rat`

**M2M token prohibited claims:**

- `gty`
- `jti`
- `scp`
